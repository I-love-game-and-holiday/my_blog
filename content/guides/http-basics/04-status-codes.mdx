## ステータスコードとは

ステータスコードは、サーバーからの「処理結果」を3桁の数字で表したものです。

  src="/guides/http/status_code.jpg"

  width={500}
  height={450}
/>

ステータスコード`200`は成功を意味しているので、上の画像はGETリクエストが成功したと分かります。

## ステータスコードの分類

ステータスコードは、最初の1桁で大まかな意味が分かります。

<ContentTable
  headers={["範囲", "分類", "意味"]}
  rows={[
    ["1xx", "情報", "処理中（あまり見かけない）"],
    ["2xx", "成功", "リクエストが正常に処理された"],
    ["3xx", "リダイレクト", "別のURLに転送された"],
    ["4xx", "クライアントエラー", "リクエストに問題がある"],
    ["5xx", "サーバーエラー", "サーバー側で問題が発生した"],
  ]}
/>

<Callout type="info">
**ステータスコードの規格**

HTTPのステータスコードは厳密に<a href="https://www.iana.org/assignments/http-status-codes/http-status-codes.xhtml" target="_blank" rel="noopener noreferrer">定義</a>されていますが、規格を厳密に参照して開発するというよりも、慣習的に使われている面もあります。

サービスによっては独自のステータスコードを定義したり、正式な定義とは異なる使い方をしている場合もあります。

</Callout>

## よく使うステータスコード

### 2xx - 成功

リクエストが正常に処理されたときのコードです。

<ContentTable
  headers={["コード", "名前", "意味", "使用例"]}
  rows={[
    ["200", "OK", "リクエスト成功", "GET, PUT, DELETEの成功"],
    ["201", "Created", "新しいリソースが作成された", "POSTの成功"],
    ["204", "No Content", "成功したが返すデータがない", "DELETEの成功"],
  ]}
/>

```
GET /users/1    → 200 OK（ユーザー情報を返す）
POST /users     → 201 Created（作成したユーザー情報を返す）
DELETE /users/1 → 204 No Content（何も返さない）
```

### 4xx - クライアントエラー

リクエストに問題があるときのコードです。**クライアント（リクエストを送った側）が原因**です。

<ContentTable
  headers={["コード", "名前", "意味", "使用例"]}
  rows={[
    ["400", "Bad Request", "リクエストの形式が不正", "必須項目が欠けている、JSONの形式が間違っている"],
    ["401", "Unauthorized", "認証が必要", "ログインしていない、トークンが無効"],
    ["403", "Forbidden", "アクセス権限がない", "他人のデータを編集しようとした"],
    ["404", "Not Found", "リソースが見つからない", "存在しないURLにアクセス、削除済みのデータ"],
    ["409", "Conflict", "競合が発生した", "同じメールアドレスで登録しようとした"],
  ]}
/>

<Callout type="info">
**401 と 403 の違い**

- **401 Unauthorized**: 「あなたが誰か分からない」（認証の問題）
- **403 Forbidden**: 「あなたが誰かは分かるが、権限がない」（認可の問題）

例えば、ログインしていない状態でアクセスすると 401、ログインしているが権限がないページにアクセスすると 403 です。
</Callout>

### 5xx - サーバーエラー

サーバー側で問題が発生したときのコードです。**サーバーが原因**です。

<ContentTable
  headers={["コード", "名前", "意味", "使用例"]}
  rows={[
    ["500", "Internal Server Error", "サーバー内部でエラーが発生", "コードのバグ、予期しない例外"],
    ["502", "Bad Gateway", "中継サーバーが不正な応答を受けた", "バックエンドサーバーがダウン"],
    ["503", "Service Unavailable", "サービスが一時的に利用不可", "メンテナンス中、過負荷"],
  ]}
/>

5xxエラーが出たら、サーバーのログを確認して原因を調査する必要があります。

API開発者としては、クライアントがエラーを適切に処理できるよう、状況に応じた正確なステータスコードを返すことが重要です。
