## プルリクエストとは

**プルリクエスト（Pull Request、略して PR）** は、GitHub 上で「この変更を取り込んでください」と依頼する仕組みです。

ブランチで作った変更を main にマージする前に、チームメンバーに **レビュー（確認）** してもらうための機能です。

## なぜプルリクエストを使うのか

直接 main にマージすることもできますが、プルリクエストを使うことで以下のメリットがあります。

- **コードレビュー**: 他の人に変更内容を確認してもらえる
- **議論**: コードについてコメントで議論できる
- **品質の維持**: 問題のあるコードが main に入るのを防げる
- **記録**: 何のために、どんな変更をしたかの記録が残る

## プルリクエストの流れ

<FlowDiagram
  steps={[
    "ブランチを作る",
    "変更してコミット",
    "GitHub に push",
    "PR を作成",
    "レビュー",
    "マージ",
  ]}
/>

1. **ブランチを作る**: main から新しいブランチを作成
2. **変更してコミット**: ブランチ上でコードを変更し、コミット
3. **GitHub に push**: ローカルの変更を GitHub に送る
4. **PR を作成**: GitHub 上でプルリクエストを作る
5. **レビュー**: チームメンバーが変更内容を確認
6. **マージ**: 問題なければ main にマージ

## 個人開発でも使おう

「一人で開発しているから PR は要らない」と思うかもしれません。

しかし、個人開発でもプルリクエストを使うメリットがあります。

- 変更内容を振り返りやすい
- main を常に安定した状態に保てる
- チーム開発に参加するときの練習になる
