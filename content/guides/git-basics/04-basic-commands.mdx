## 基本コマンドの全体像

Git の基本コマンドは、大きく分けて **3つの場面** で使います。

1. **リポジトリの準備**
2. **変更の記録**
3. **履歴の確認**


## リポジトリの準備
ワーキングツリーで変更履歴を保存するための前準備として`git init`コマンドを使用します。これは一度のみ使用します。

このコマンドを実行すると履歴を保存できるようになります。

  headers={["コマンド", "何をするか"]}
  rows={[
    ["git init", "ワーキングツリーでの作業を記録するための前準備"],
  ]}
/>

## 変更の記録

<FlowDiagram
  steps={[
    "ファイルを編集",
    "git add（ステージに追加）",
    "git commit（コミット）",
  ]}
/>

『Gitの仕組み』ガイドの通り、編集したファイルは一度ステージング状態にした後に記録を保存します。<br/>
コミットする際は`-m`でメッセージを添えるルールになっています。

後から見たときにどんな内容の変更かコミットメッセージを見ただけで
思い出せるくらい分かりやすく、具体的に残すのがベストです。


<ContentTable
  headers={["コマンド", "何をするか"]}
  rows={[
    ["git add ファイル名", "変更をステージに追加する"],
    ["git commit -m \"メッセージ\"", "ステージの内容をコミットする"],
  ]}
/>

## 履歴の確認

<ContentTable
  headers={["コマンド", "何をするか"]}
  rows={[
    ["git status", "現在の状態を確認する（変更があるか、ステージに何があるか）"],
    ["git log", "コミット履歴を一覧で見る"],
    ["git diff", "まだステージしていない変更の差分を見る"],
  ]}
/>

<Callout type="info">
**`git status` は最も使うコマンドです。** 迷ったらまず `git status` を打ちましょう。

gitの操作はミスしてチームに迷惑をかけてしまう可能性がありますが、このコマンドに関しては状態を確認するだけなので
気軽に利用できます。どんどん使ってみましょう。
</Callout>
