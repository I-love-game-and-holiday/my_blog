## このコースで作るもの

TypeScript + Express を使って、**勤怠管理API** を作ります。

従業員の出勤・退勤を管理するシステムのバックエンド部分です。ブラウザやアプリから送られてくるリクエストを受け取り、データを処理して返す **REST API** を実装します。

## REST API とは

**REST API** は、Webアプリケーション間でデータをやり取りするための仕組みです。

普段あなたがWebサイトを見るとき、ブラウザは裏側でサーバーと通信しています。REST APIはその通信の「ルール」を定めたものです。

### 身近な例

スマホの天気アプリを想像してください。

```
1. アプリが「東京の天気を教えて」とサーバーにリクエストを送る
2. サーバーが天気データを探す
3. サーバーが「晴れ、25℃」とレスポンスを返す
4. アプリが画面に表示する
```

この「リクエストを送る → レスポンスを受け取る」のやり取りがAPIの基本です。

### HTTPメソッド

REST APIでは、**HTTPメソッド** で「何をしたいか」を表現します。

<ContentTable
  headers={["メソッド", "意味", "例"]}
  rows={[
    ["GET", "データを取得する", "勤務記録の一覧を取得"],
    ["POST", "データを作成する", "新しい出勤記録を作成"],
    ["PUT", "データを更新する", "打刻時刻を修正する"],
    ["DELETE", "データを削除する", "記録を削除する"],
  ]}
/>

<Callout type="info">
この4つの操作は **CRUD** と呼ばれます。

**C**reate（作成）、**R**ead（読取）、**U**pdate（更新）、**D**elete（削除）の頭文字です。コース1のTodoアプリでも同じ操作を実装しましたね。
</Callout>

### エンドポイント

APIの「住所」にあたるものを **エンドポイント** と呼びます。

このコースで作るエンドポイントは以下の通りです。

<ContentTable
  headers={["メソッド", "パス", "機能"]}
  rows={[
    ["GET", "/records", "勤務記録の一覧取得"],
    ["GET", "/records/:id", "特定の勤務記録を取得"],
    ["POST", "/records/clock-in", "出勤打刻"],
    ["POST", "/records/clock-out", "退勤打刻"],
    ["PUT", "/records/:id", "打刻の修正"],
    ["DELETE", "/records/:id", "記録の削除"],
  ]}
/>

`:id` の部分には実際のIDが入ります（例: `/records/1`）。

### データベースについて

このコースでは **データベースは使いません**。

データはTypeScriptの配列（インメモリ）で管理します。サーバーを再起動するとデータはリセットされますが、API開発の学習に集中するためにこの方式を採用しています。
